# LocalChats · Sales Console

Единый инбокс мессенджеров для отдела продаж: рабочие и личные WhatsApp/Telegram в одном
интерфейсе, с UTM-атрибуцией входящих и режимом **inbound-only** (только ответы на входящие,
без рассылок).

## Возможности

- **Единый инбокс** — рабочие номера компании и личные номера сотрудников в одном списке диалогов; личная переписка видна только владельцу номера.
- **Подключение номеров по QR** — прямая сессия через воркер (Evolution API для WhatsApp, gramjs для Telegram), как в WhatsApp Web. Без Business-пакетов.
- **UTM-атрибуция** — метка `#XXXXXXXX` из deep link → `exact`; матчинг по недавнему клику → `fallback`; остальное → `direct`. Экспорт GCLID в CSV для Google Ads.
- **Демо и прод** — демо-режим (симулятор входящих, фейковый QR) для тестов интерфейса, прод-режим с реальными сессиями через воркер.
- **Переключаемая архитектура данных** — localStorage, Supabase или любой собственный REST-сервер; меняется в настройках без потери данных.

## Быстрый старт

```bash
npm install
npm run dev      # локальная разработка
npm run build    # продакшен-сборка в dist/
```

- **Демо-режим** работает сразу после входа, без каких-либо серверов.
- **Прод-режим**: Настройки/Админка → Интеграции → указать URL и API-ключ воркера сессий,
  переключить режим на «Продакшен».
- **Архитектура данных**: Настройки → «Архитектура данных» → выбрать localStorage / Supabase / REST.

## Стек

- **Frontend**: React 19 + Vite + TypeScript, один реактивный стор (`useSyncExternalStore`), без внешних стейт-менеджеров.
- **Auth**: Verdent-managed Supabase Auth (Google / email+password) через `@verdent/auth-js`.
- **Данные**: подключаемый слой `DataBackend` (см. [docs/backend-adapters.md](backend-adapters.md)).
- **Воркер сессий**: Evolution API (WhatsApp-личные) + gramjs (Telegram-личные) на отдельном контейнере; контракт — `src/lib/worker.ts`.
- **Схема БД** (этап 2): `supabase/schema.sql`.
